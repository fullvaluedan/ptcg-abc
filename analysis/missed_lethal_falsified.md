# The "missed lethal" lead is a detector artifact, not a heuristic bug

## Question

The endgame_misplay bucket (near-win losses where we needed only 1 to 2 prizes)
suggested the heuristic might be passing up guaranteed knockouts. If true, that is
a concrete, high-value fix: never miss a lethal. This note records the
investigation and why the lead was falsified, so a future iteration does not
re-walk it.

## What was built

An offline detector that, for every lost game, replays each of our ACTIVE MAIN
decisions and calls `heuristics.lethal_move(obs)` on the recorded observation. If
that returns an attack index and the recorded `action` differs, it counts as a
"missed lethal". Card data is available offline (`heuristics.attack_index()`
loads 1556 attacks), so `effective_damage` (with weakness x2 and resistance cut)
is computed exactly as the live agent computes it.

## The apparent finding

The detector flagged 11 of 19 losses, including current-generation games. One game
(episode 82876630, the v1 deckout-guard agent) showed 59 "missed lethals", and an
older game showed 71. That count alone is a tell: a real guaranteed knockout ends
the game and takes a prize, so you cannot decline one 59 times in a single match.

## Adversarial check (decisive)

For every flagged step, `heuristics.choose(obs)` returns the SAME index as
`lethal_move(obs)`. So the current heuristic, by construction, WOULD take every
lethal the detector says we missed. The recorded `action`, however, was a
different option (typically `[0]` or `[]`).

To settle whether this is a real bug or a detector artifact, the detector was run
on FRESH self-play replays generated by the CURRENT heuristic (`env.toJSON()`,
same replay format). The live agent there IS `choose()`, so it cannot miss a
lethal it computes. The detector still reported 2 "missed lethals" across 6 fresh
games. Since those are impossible-by-construction, the detector overcounts.

## Root cause of the false positives

At a SEL_MAIN select the recorded `action` does NOT align with
`lethal_move(obs)` on the same step entry. Agreement between `choose(obs)` and the
recorded action is high for SEL_CARD (12 of 13 in one game) but low for SEL_MAIN
(10 of 76 in the same game). A turn is a sequence of MAIN sub-decisions (play,
attach, then attack or end), and the observation/action pairing the replay records
at a MAIN sub-step is not the (obs in, action out) pair the agent actually
evaluated for that step. Comparing `lethal_move(obs_t)` to `action_t` at MAIN is
therefore apples to oranges. The detector is not trustworthy and was not shipped.

## Conclusion

There is no verified missed-lethal bug. `choose()` and `lethal_move()` agree, and
the live agent provably takes the lethals it computes. endgame_misplay losses are
genuine board losses (the opponent out-raced us or healed back, e.g. episode
82875976 where the opponent active healed from 100 HP to its full 300 HP), not
declined knockouts. No heuristic change is justified by this lead, and changing
the lethal path would risk the current ladder best for no measured gain.
