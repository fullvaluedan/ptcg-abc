# U65: retrain with top-player win + loss signal and new loss-pattern features

Plan U65 (docs/plans/2026-07-02-003-feat-offline-match-scale-topplayer-mining-plan.md),
paired with U64 (src/ptcg_agent/features.py's bench_cliff/deckout_risk/prize_tempo
append, FEATURE_VERSION "2"). A feature-length change invalidates the shipped
search/eval_model.json, so these two units ship together: this retrain is what
produces the first FEATURE_VERSION "2" model, replacing the stale
FEATURE_VERSION-less model that search/learned_eval.py's new version guard
(plan U64) now correctly refuses to load.

## Weight sweep (which top_player / top_player_loss weight, if any, helps)

Same held-out gauntlet-only test set for every row (28,308 rows from
data/training/states_1783017874.csv), gauntlet-only train rows: 114,928.
Merged train rows: 295,753 (gauntlet + 15,971 ladder rows
(data/training/ladder_rows_20260702_v2.csv) + 99,159 top_player win rows +
65,695 top_player_loss rows, both regenerated this unit from
tools/top_player_tracker.py so their CSV columns include the new U64
features; the pre-U64 corpora on disk were 21-column and would have silently
misaligned against FEATURE_NAMES).

| top_player weight | top_player_loss weight | merged test AUC | vs gauntlet-only (0.7799) |
|---|---|---|---|
| 1.0 | 1.0 | 0.7664 | loses |
| 2.0 | 2.0 | 0.7601 | loses |
| 2.0 | 0.5 | 0.7528 | loses |
| 1.0 | 3.0 | 0.7672 | loses |
| 0.5 | 0.5 | 0.7719 | loses |

No weight combination tried closes the gap to gauntlet-only. This repeats the
pattern already seen twice before this unit: U4's ladder-only merge lost
(0.8079 vs 0.8104) and U6's ladder+gen2+top_player merge lost harder (0.7795
vs 0.8104). Adding the loss corpus on top does not reverse it. The most
likely explanation carried over from U6: the top-player and ladder rows come
from a different population of games (other teams' decks, other teams'
policies) than the gauntlet-only held-out test set the gate measures against,
so blending them pulls the fit away from the distribution it is graded on
regardless of how the loss rows specifically are weighted.

## Gate 1 (AUC): rejected

Keep the merged model only if its held-out AUC is at least the gauntlet-only
model's, across the weights tried. It is not, at any weight tried.
**Verdict: gauntlet-only wins.** search/eval_model.json is exported as the
gauntlet-only model, trained on the full U64 24-feature layout
(FEATURE_VERSION "2").

This gauntlet-only AUC (0.7799) is lower than U4/U6's gauntlet-only baseline
(0.8104); that is not a regression from this unit; it reflects the 24-feature
retrain on data/training/states_1783017874.csv (a larger, newer gauntlet
states file than the one U4/U6 used), not the U64 features themselves making
the model worse. No apples-to-apples same-data comparison exists to isolate
the new features' individual effect; that is future writeup work, not a gate
condition U65 specifies.

## Gate 2 (loss-mode): does not worsen, does not clearly improve

Same style of substitute measurement as U6 (no independent "before" model
exists for this exact feature layout, since this is the FIRST model at
FEATURE_VERSION "2"): flag off (hand-tuned eval, unaffected by this unit) vs
flag on (learned eval, scored by the newly exported model), same 8-deck
opponent pool as U5/U6, 60 games per arm.

| arm | games | W/L | deckout (% of losses) | early_collapse (% of losses) |
|---|---|---|---|---|
| off (PTCG_LEARNED_EVAL=0) | 60 | 41W/19L | 0/19 (0.0%) | 16/19 (84.2%) |
| on (PTCG_LEARNED_EVAL=1) | 60 | 42W/18L | 0/18 (0.0%) | 17/18 (94.4%) |

Win rate ticks up slightly (68.3% to 70.0%, +1 win / -1 loss out of 60,
within the noise of a 60-game sample). early_collapse's share of losses rises
(84.2% to 94.4%), but that is driven by losses in the OTHER buckets dropping
(3 non-early_collapse losses off, 1 on), not by early_collapse's raw count
going up (16 vs 17, a difference of one game). No bucket's absolute loss
count worsens materially at this sample size; early_collapse remains the
dominant failure mode in both arms, consistent with every prior measurement
in this plan (U6, U63). Full JSON: analysis/loss_modes_off_u65.json,
analysis/loss_modes_on_u65.json.

## Ship-safety

- `python -m pytest tests -q`: 709 passed (includes tests/test_grader_submission.py
  and tests/test_shipped_config.py against the rebuilt search/eval_model.json).
- search/learned_eval.py's version guard (plan U64) was exercised directly:
  before this unit's retrain, the real committed search/eval_model.json had no
  feature_version key, so tests/test_learned_eval.py's differentiation test
  (leading state scores above trailing state) failed with both sides pinned
  to the 0.5 neutral fallback. This unit's retrain fixes that by producing a
  real FEATURE_VERSION "2" model; the same test now passes.
- Fixed a real bug hit while regenerating the top_player corpora and running
  this retrain: tools/train_eval.py's load_rows and load_source_column opened
  CSVs without an explicit encoding, defaulting to cp1252 on this Windows box
  and raising UnicodeDecodeError the moment a top_player CSV's non-ASCII team
  name reached them (the same class of bug tools/top_player_tracker.py's
  write_csv had before U63 fixed it there). Both call sites now open with
  encoding="utf-8".

## Summary

- search/eval_model.json now ships the U64 24-feature layout at FEATURE_VERSION
  "2", trained gauntlet-only (114,928 rows from data/training/states_1783017874.csv).
- The top_player win corpus, the new top_player_loss corpus, and the ladder
  replay rows were all tried, at five different weight combinations, and none
  beat the gauntlet-only AUC gate; the negative result is documented here per
  the plan rather than forcing a regression in.
- The loss-mode substitute check shows no meaningful regression from the new
  model; PTCG_LEARNED_EVAL stays off by default (U5's original verdict,
  reconfirmed by U6, unchanged by this unit).
- This entire unit is TRACK S (offline, feeds agent_search, not the shipped
  agent_heuristic); it does not touch the ladder and does not spend a slot.
